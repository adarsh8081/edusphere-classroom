1. Parent Accounts & Dashboard
Overview
Introduce a new role: parent. Parents can be linked to one or more students. They get a read‑only dashboard to monitor their child’s classes, assignments, attendance, and grades.

Database Additions
sql
-- Parents table (links parent to student)
CREATE TABLE parent_students (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  parent_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  student_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  UNIQUE(parent_id, student_id)
);

-- Add 'parent' to users role check (ALTER TYPE if using enum, or just allow in application)
-- You may need to modify the users table role constraint to include 'parent'.
API Endpoints
Method	Endpoint	Description	Auth
POST	/parents/link	Link parent to student (teacher or admin only)	Teacher
GET	/parents/children	List all students linked to the authenticated parent	Parent
GET	/parents/child/:id/dashboard	Get aggregated dashboard for a specific child (classes, upcoming assignments, recent grades, attendance)	Parent
Frontend Components
Parent Registration/Login: Parents register via invite link (sent by teacher). They should be able to sign up and then link to their child using a code or email verification.

Parent Dashboard: After login, parent sees a list of linked children. Clicking a child shows a dashboard with:

List of classes (with links to read‑only views).

Upcoming assignments (with due dates).

Recent grades (with links to assignment details).

Attendance summary (percentage, recent absences).

Stream posts (read‑only, no commenting).

Read‑only Class Views: Parents can view class stream, classwork, people, and grades tabs – but all interactions are disabled (no posting, submitting, etc.).

Notifications for Parents
Parents receive notifications (in‑app and email) when their child gets a new grade, when an assignment is due soon, or when attendance is marked absent.

2. Advanced Real‑time Communication
Direct Messaging
Allow one‑to‑one messaging between:

Teacher ↔ Student

Teacher ↔ Parent

Student ↔ Student (opt‑in, can be disabled by teacher)

Group Chats
Teachers can create study groups (e.g., "Project Alpha Team") within a class. Group has its own chat room.

Database Additions
sql
-- Conversations (for direct and group messages)
CREATE TABLE conversations (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  type TEXT NOT NULL CHECK (type IN ('direct', 'group')),
  name TEXT, -- for group chats
  class_id UUID REFERENCES classes(id) ON DELETE CASCADE, -- for group chats
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Conversation participants
CREATE TABLE conversation_participants (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  conversation_id UUID NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  joined_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  UNIQUE(conversation_id, user_id)
);

-- Messages
CREATE TABLE messages (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  conversation_id UUID NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
  sender_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  content TEXT NOT NULL,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE
);

-- Read receipts (optional)
CREATE TABLE message_reads (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  message_id UUID NOT NULL REFERENCES messages(id) ON DELETE CASCADE,
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  read_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  UNIQUE(message_id, user_id)
);
API Endpoints
Method	Endpoint	Description	Auth
GET	/conversations	List user's conversations (with last message)	User
POST	/conversations/direct	Create a direct conversation with another user	User
POST	/conversations/group	Create a group chat (teacher only)	Teacher
GET	/conversations/:id/messages	Get messages in a conversation (paginated)	Participant
POST	/conversations/:id/messages	Send a message	Participant
PATCH	/messages/:id	Edit own message (within time limit)	Owner
DELETE	/messages/:id	Delete own message (soft delete optional)	Owner
POST	/conversations/:id/participants	Add participant to group (teacher only)	Teacher
DELETE	/conversations/:id/participants/:userId	Remove participant (teacher or self)	Teacher/self

3. Enhanced Stream Features
Polls
Teachers can create a poll (multiple choice, single/multiple answers) in the stream.

Students can vote once (or change vote if allowed).

Results are visible after voting (or after poll closes).

Database Additions:

sql
CREATE TABLE polls (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  post_id UUID UNIQUE NOT NULL REFERENCES posts(id) ON DELETE CASCADE,
  question TEXT NOT NULL,
  multiple_answers BOOLEAN DEFAULT FALSE,
  closes_at TIMESTAMP WITH TIME ZONE -- optional
);

CREATE TABLE poll_options (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  poll_id UUID NOT NULL REFERENCES polls(id) ON DELETE CASCADE,
  option_text TEXT NOT NULL,
  position INT NOT NULL
);

CREATE TABLE poll_votes (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  poll_id UUID NOT NULL REFERENCES polls(id) ON DELETE CASCADE,
  option_id UUID NOT NULL REFERENCES poll_options(id) ON DELETE CASCADE,
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  UNIQUE(poll_id, user_id, option_id) -- for multiple answers, need composite; better to allow multiple votes per user per poll, but we'll enforce per option
);
API Endpoints:

POST /classes/:id/polls – create a poll (attached to a new post).

GET /polls/:id – get poll details with options and current vote counts.

POST /polls/:id/vote – vote on an option (toggle if multiple allowed).

Scheduled Announcements
Teachers can schedule a post to be published later.

Add scheduled_at column to posts table (nullable).

A background job (cron) runs every minute to publish scheduled posts.

Auto‑translation
Integrate Google Cloud Translation API (or similar) to translate posts and comments.

Add a "Translate" button next to each post/comment for users.

Store user language preference (add language field to users table).

4. Classwork Improvements
Resource Versioning
When a teacher updates a resource (re-upload), keep old versions.

Add a version column to resources table, or create a separate resource_versions table.

For MVP, we can simply update the file URL and keep a history log (optional).

Simpler approach: Add previous_versions JSONB column to resources storing an array of old file URLs and timestamps.

Prerequisites
Teachers can mark an assignment or resource as a prerequisite for another.

Students cannot access a dependent item until they have completed the prerequisite (e.g., submitted assignment, viewed resource).

Database:

sql
CREATE TABLE prerequisites (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  dependent_on_id UUID NOT NULL, -- the item that must be completed (assignment or resource)
  dependent_on_type TEXT NOT NULL CHECK (dependent_on_type IN ('assignment', 'resource')),
  required_for_id UUID NOT NULL, -- the item that requires completion
  required_for_type TEXT NOT NULL CHECK (required_for_type IN ('assignment', 'resource')),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
Enforcement: When a student tries to access an assignment/resource, check prerequisites. If not met, show a message.

Peer Review Assignments
Teachers can create an assignment that requires students to review peers' submissions.

Add peer_review flag to assignments, and review_deadline.

After submission deadline, randomly assign each student a set of peer submissions to review.

Create reviews table to store peer feedback and scores.

Database:

sql
ALTER TABLE assignments ADD COLUMN is_peer_review BOOLEAN DEFAULT FALSE;
ALTER TABLE assignments ADD COLUMN review_deadline TIMESTAMP WITH TIME ZONE;
ALTER TABLE assignments ADD COLUMN reviews_per_student INT DEFAULT 2;

CREATE TABLE reviews (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  assignment_id UUID NOT NULL REFERENCES assignments(id) ON DELETE CASCADE,
  reviewer_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  submission_id UUID NOT NULL REFERENCES submissions(id) ON DELETE CASCADE,
  content TEXT,
  score DECIMAL(5,2),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  UNIQUE(assignment_id, reviewer_id, submission_id)
);
API: Teacher can trigger assignment of reviews; students see a list of submissions to review.

6. Basic Teacher Analytics
Engagement Heatmap
Show teachers which students are actively engaging: viewing resources, participating in discussions, submitting on time.

Compute a simple engagement score (based on login frequency, resource views, comments, submissions).

Data Collection:

Add a user_activities table to log events (view resource, comment, login, etc.).

sql
CREATE TABLE user_activities (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  class_id UUID NOT NULL REFERENCES classes(id) ON DELETE CASCADE,
  activity_type TEXT NOT NULL, -- 'view_resource', 'create_comment', 'submit_assignment', 'login'
  reference_id UUID, -- optional id of related entity
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
Assignment Stats

Submission rate (percentage of students who submitted)

Average score

Score distribution (histogram)

Late submissions count
