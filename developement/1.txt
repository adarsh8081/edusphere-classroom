Phase 1 – Foundation & Core Classroom (MVP)
Goals
User authentication with roles (Teacher, Student).

Teachers can create classes, students can join via class code.

Stream tab: real‑time discussion with posts, comments, reactions.

Classwork tab: topics, resource uploads, assignments with submissions.

People tab: roster, invites.

Attendance module: mark and view attendance.

Basic gradebook: teachers can grade submissions.

In‑app notifications for key events.

Detailed Feature List
1. User Authentication & Role‑Based Access Control (RBAC)
Roles: super_admin, teacher, student. (Parent will be added in Phase 2.)

Registration: email, password, name, role (only teacher/student for now). For simplicity, we may not allow public registration for teachers – they could be created by a super admin, but for MVP allow any user to register as teacher or student (we'll add restrictions later). Include a checkbox for "I am a teacher".

Login: email + password, return JWT.

Profile: user can view and edit basic info (name, avatar). Avatar upload to S3.

2. Class Management
Create Class (teacher only): name, subject, grade, description. System generates a unique class code (e.g., random 6‑character alphanumeric).

Join Class (student only): enter class code to enroll.

Each class has a unique ID and a dashboard.

3. Stream Tab (Real‑time Discussion)
Posts: Teachers can create text posts (announcements) with optional file attachments (upload to S3). Posts belong to a class.

Comments: Any class member can comment on posts (threaded – support replies). Comments are real‑time via WebSockets.

Reactions: Users can react to posts and comments with emojis (👍, ❤️, 😕, etc.). One reaction per user per target per emoji (toggle on/off).

Pinned Posts: Teachers can pin/unpin posts. Pinned posts appear at the top.

Real‑time updates: When a new post/comment/reaction is created, all users in that class should see it instantly (using Socket.io rooms).

4. Classwork Tab (Resource & Assignment Hub)
Topics: Teachers can create topics (folders) to organize content (e.g., "Chapter 1", "Homework"). Topics have a position order.

Resources: Teachers can upload files (PDF, images, videos) to a topic. Each resource has a title (optional, defaults to filename), file URL, and file type.

Assignments:

Teachers can create assignments under a topic (or no topic). Fields: title, instructions (rich text optional), due date, max points, optional attachments.

Students can submit: either text response or file upload (or both). Allow multiple submission attempts? For MVP, one submission per student, but allow resubmission until due date? Let's allow updates until due date.

Teachers can view all submissions for an assignment, enter a grade (decimal) and feedback. Grades are stored.

Submissions are timestamped.

5. People Tab
Roster: List all students and teachers in the class. Show role, join date.

Invites: Teacher can copy class code to share. Optionally send email invites (for MVP, just display the code; we can add email later).

Teacher can remove a student from the class.

6. Attendance Module
Mark Attendance: Teacher selects a date and marks each student as present/absent/late. For MVP, a simple list with checkboxes.

View Attendance: Students can see their own attendance record (list of dates with status). Teachers can view full class attendance for a date range.

7. In‑app Notifications
Users receive notifications for:

New post in a class they are in.

New comment on their post or comment they participated in.

Assignment created (for students in that class).

Grade published (for the student).

Notifications have type, reference ID (e.g., post ID), content preview, read/unread status.

API to fetch notifications and mark as read.

Database Schema (PostgreSQL)
Please create the following tables. Use UUID for primary keys. Provide SQL migration scripts.

sql
-- Users
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  name TEXT NOT NULL,
  role TEXT NOT NULL CHECK (role IN ('super_admin', 'teacher', 'student')),
  avatar_url TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Classes
CREATE TABLE classes (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  subject TEXT,
  grade TEXT,
  description TEXT,
  class_code TEXT UNIQUE NOT NULL,
  teacher_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Enrollments
CREATE TABLE enrollments (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  class_id UUID NOT NULL REFERENCES classes(id) ON DELETE CASCADE,
  student_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  joined_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  UNIQUE(class_id, student_id)
);

-- Posts
CREATE TABLE posts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  class_id UUID NOT NULL REFERENCES classes(id) ON DELETE CASCADE,
  author_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  content TEXT NOT NULL,
  is_pinned BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE
);

-- Post attachments (files)
CREATE TABLE post_attachments (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  post_id UUID NOT NULL REFERENCES posts(id) ON DELETE CASCADE,
  file_url TEXT NOT NULL,
  file_type TEXT, -- e.g., 'image/png', 'application/pdf'
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Comments
CREATE TABLE comments (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  post_id UUID NOT NULL REFERENCES posts(id) ON DELETE CASCADE,
  author_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  parent_id UUID REFERENCES comments(id) ON DELETE CASCADE,
  content TEXT NOT NULL,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE
);

-- Reactions
CREATE TABLE reactions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  post_id UUID REFERENCES posts(id) ON DELETE CASCADE,
  comment_id UUID REFERENCES comments(id) ON DELETE CASCADE,
  emoji TEXT NOT NULL,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  CONSTRAINT reaction_target_check CHECK (
    (post_id IS NOT NULL AND comment_id IS NULL) OR
    (post_id IS NULL AND comment_id IS NOT NULL)
  ),
  UNIQUE(user_id, post_id, comment_id, emoji)
);

-- Topics
CREATE TABLE topics (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  class_id UUID NOT NULL REFERENCES classes(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  position INTEGER NOT NULL DEFAULT 0,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Resources
CREATE TABLE resources (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  topic_id UUID NOT NULL REFERENCES topics(id) ON DELETE CASCADE,
  uploader_id UUID NOT NULL REFERENCES users(id) ON DELETE SET NULL,
  title TEXT,
  file_url TEXT NOT NULL,
  file_type TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Assignments
CREATE TABLE assignments (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  class_id UUID NOT NULL REFERENCES classes(id) ON DELETE CASCADE,
  topic_id UUID REFERENCES topics(id) ON DELETE SET NULL,
  title TEXT NOT NULL,
  instructions TEXT,
  due_date TIMESTAMP WITH TIME ZONE,
  max_points INTEGER,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  created_by UUID REFERENCES users(id) ON DELETE SET NULL
);

-- Assignment attachments (optional files for the assignment description)
CREATE TABLE assignment_attachments (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  assignment_id UUID NOT NULL REFERENCES assignments(id) ON DELETE CASCADE,
  file_url TEXT NOT NULL,
  file_type TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Submissions
CREATE TABLE submissions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  assignment_id UUID NOT NULL REFERENCES assignments(id) ON DELETE CASCADE,
  student_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  content TEXT, -- text submission
  file_url TEXT, -- file submission (if any)
  submitted_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  grade DECIMAL(5,2),
  feedback TEXT,
  graded_at TIMESTAMP WITH TIME ZONE,
  UNIQUE(assignment_id, student_id)
);

-- Attendance
CREATE TABLE attendance (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  class_id UUID NOT NULL REFERENCES classes(id) ON DELETE CASCADE,
  student_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  date DATE NOT NULL,
  status TEXT NOT NULL CHECK (status IN ('present', 'absent', 'late')),
  marked_by UUID NOT NULL REFERENCES users(id) ON DELETE SET NULL,
  marked_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  UNIQUE(class_id, student_id, date)
);

-- Notifications
CREATE TABLE notifications (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  type TEXT NOT NULL, -- e.g., 'new_post', 'new_comment', 'assignment_created', 'grade_published'
  reference_id UUID, -- id of the related entity (post, comment, assignment, etc.)
  content TEXT NOT NULL,
  is_read BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

WebSocket Events (Socket.io)
Connection: authenticate using JWT token (sent as query param or auth handshake).

After connection, client can join a class room: join_class (with classId).

When a new post is created, server emits new_post to the class room with the post data.

When a new comment is created, server emits new_comment to the post room (or class room). We'll emit to the post room (clients who are viewing that post). Alternatively, we can emit to class room and let client filter. For simplicity, emit to class room with a type field indicating it's a comment and the post ID.

When a reaction is added/removed, emit reaction_updated to class room.

Define the event payloads clearly.

Database: Use connection pooling. Provide a migration script (e.g., using pg or a migration tool like node-pg-migrate).
